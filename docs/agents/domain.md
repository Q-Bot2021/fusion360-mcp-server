# Domain Docs

This is a single-context repository.

Before exploring domain behavior, read the root `GLOSSARY.md` and relevant
ADRs in `docs/adr/` when those files exist. If they do not exist, proceed
without flagging their absence; create them lazily when terminology or
architectural decisions need to be recorded.

Use glossary terms in issue titles, proposals, and tests. Surface conflicts
with existing ADRs instead of silently overriding them.
